# P54 原生 CA 核对结果，2026-11-11

本轮只分析镜像和生成离线数据方案，没有刷写 modem、改变射频配置或写 NV。

## 已定位到 P54 自身的消费者

通过 P72 符号与 P54 多处唯一指令锚点关联，再核对 P54 反汇编中的
调用目标和结构访问，定位如下：

| 功能 | P54 地址 | 参考函数长度 |
|---|---|---:|
| CA 查询 | 0x91076ef8 | 128 |
| CA linkage 分配 | 0x91076d32 | 454 |
| common-linkage 构造 | 0x9107422c | 210 |
| CA linkage 有效性检查 | 0x910742fe | 132 |
| 哈希键计算 | 0x91075da0 | 240 |
| 静态 CA 表到运行时表的构造 | 0x9107b818 | 2676 |

长度为跨版本定位的参考范围；地址和关键调用关系已经在 P54 代码中核对。
同名函数不能仅按版本间固定地址差推断，其他消费者仍需逐一验证。

## 修正了一个结构解析问题

40 字节的双 region 记录不是十个指针：前 36 字节是九个指针，
偏移 36/37 是两个 byte flags，末尾两字节是剩余布局字节。
P54 原生构造函数在 0x91074274/0x9107427e 对这两个位置执行 lbu。
旧比较脚本的 `pointers` 标签把最后四字节也列为指针，现已修正。
本轮新方案原样保留 flags、剩余字节和所有辅助对象引用。

## 静态哈希末项：仍不是已证实的 CA 故障原因

原生哈希函数将有效的接收频段号求和，接收列表为空时转用发射列表，
跳过大于 65532 的哨兵值，再按选定表大小取模。

P54 静态双 region 表有 104 行，其中第 103 行（LTE B41+B42）的静态
分桶范围与上述推导不一致。P70 的 1090 行则全部一致。
但是 P54 的运行时初始化不是直接把这组静态起始下标当作最终链表：

- 0x9107b8c8–0x9107b8cc 根据输入 table count 遍历记录。
- 0x9107b8f6–0x9107b90a 按 index × 40 取行。
- 0x9107b91a 调用 common-linkage 构造。
- 0x9107b968 调用 P54 自身的哈希键计算。
- 0x9107b96e/0x9107b976 取得运行时 hash head 并选择 bucket。

这条初始化路径涵盖最后一行，因此不能由静态分桶差异直接断言该行
永远不会进入运行时索引。静态查询另有调用方起点、范围和总 count 的
限制；没有把该差异当作确定 bug 写入现机或发布镜像。

## n78 的 P54 原生复用方案

两个 P54 profile 中，n77 和 n78 的四组单 region 路由在 RX unit、
TX unit、antenna 字段和 dependency 指针上逐项完全一致。
两个 profile 各自都存在 8 条原生 n77+n77 双 region 路径。

据此生成了一个局部离线方案：把这 8 条路径的 NR band 标签由 77 改为
78，其余 RF unit、辅助对象、flags 和校准引用全部保持 P54 本身的值。
每个 profile 的拟议表由 104 行增加至 112 行，原 104 行逐字节保留。

候选能力节点取 P54 自身原节点 22，只将其两个 n77 标签改为 n78：
`4d0000004d001100` → `4e0000004e001100`。
HW、SRS、HPUE、功率配置保持该 P54 节点原值。

这个节点的表示是两个 class-A band entries。它与先前 P70 donor 的
单个 class-B entry 不相同，不能把两者当成同一种连续/非连续 CA 拓扑。
后续仍须对照 region 构造、频率放置、RF 带宽和天线路由验证。

进一步核对校准表发现：两个 profile 的 NR RX1、RX2、TX 三组中，
n77 与 n78 的 route/slot 配对逐项一致，但校准记录的模式字段分别为
0 和 1。这是六组都出现的真实差异。RF unit 相同不能证明校准初始化
等价；本方案没有把 n78 的模式强制改成 0，后续必须追踪原生消费者。
`audit_n78_calibration_modes.py` 已逐组验证并保存完整配对数据。

**产物是离线 arena 和 manifest，不是 modem 镜像，也没有进入发布构建。**
0x93000000 仅用于本地重定位验证，不是选定的 P54 部署地址。
每个 arena 为 4932 字节。没有复制任何 P70 可执行代码、授权逻辑或校准。

## 本轮验证

`verify_n78_native_rf_plan.py` 退出 0，两个 profile 均通过：

```text
112 rows, 104 original byte-preserved, 8 native aliases,
flags/aux unchanged, 29 buckets, capability parallel data unchanged
PASS baseline unchanged; device writes=0; plan is not a modem image
```

生成后重新读取 arena 与 manifest，验证 SHA256、九个指针/flags 布局、
所有原始行的完整保留、8 条新增行的 band 改写及哈希分桶范围。
原始 P54 镜像的 SHA256 前后保持一致。
